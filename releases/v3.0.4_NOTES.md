## Highlights in v3.0.4

### 1. Stale Parquet Cache Elimination & DuckDB View Auto-Heal
Fixes the `IO Error: No files found that match the pattern ".../temp/<old_project_id>/...parquet"` error that could appear after deleting projects, purging cache, or reopening the same source file under a newly created project.

- **Synchronized Backend View & Mapping Invalidation (`state.rs`, `workspace.rs`, `parquet_ledger.rs`)**:
  - `handle_delete_project`, `handle_delete_all_projects`, `handle_purge_cache`, and `handle_remove_file` now drop affected DuckDB `tbl_<hash>` views immediately, evict stale `view_parquet_paths` entries, and emit a `cache:invalidate` event to the frontend.
- **Self-Healing DuckDB Query Layer (`query.rs`)**:
  - `row_count_with_state` verifies that the mapped backing Parquet file still exists on disk; if missing, `try_rebind_stale_table_view` automatically scans live `temp/<project_id>/` directories for the relocated `<hash>.parquet`, rebinds the DuckDB `VIEW`, updates `view_parquet_paths`, and returns accurate O(1) row counts without error.
- **Frontend RAM Micro-Cache Synchronization (`MultipleLoadingManager.ts`, `ProjectWorkspaceManager.ts`, `actions.ts`)**:
  - `deleteAllProjects()` clears all in-memory pre-warm cache items (`clearAllItems()`), `purgeProjectCache()` evicts only the affected project's file entries (`invalidateFilesCache()`), and `replaceCurrentView()` ensures the active DuckDB view is bound to the live Parquet file even on a RAM cache hit.

### 2. Includes v3.0.3 Wide-Table & 7-Layer Laptop Peak-Performance Baseline
- **SQL Column Pruning & Adaptive Sliding Buffer (`PivotRequester.ts`, `QueryView.ts`, `PagedDataView.ts`)**: Projects visible columns (default cap 100), enforces byte-bounded RAM cache (`48 MB` cap / `12` entries / `<= 16 MB` per entry), and eliminates blank rows on partial cache views.
- **Host-Aware DuckDB Resource Governor & Cancellable Arrow IPC (`duckdb_pool.rs`, `arrow_encoder.rs`, `io_monitor.rs`, `scheduler.rs`)**: Clamps UI/worker memory and threads dynamically based on host RAM/disk, interrupts superseded interactive queries (`30s` watchdog), caps Arrow IPC streams (`64 MB` / `2M` cells), and isolates `SUMMARIZE` (100-column cap).
- **On-Demand Full-Row `EventDetailSidebar` & Inline Error Recovery (`AppPane.tsx`, `EventDetailSidebar.tsx`, `Footer.tsx`)**: Instant `0 ms` sidebar open with async full-schema hydration and inline footer retry controls.
